Abstract

A summary of the paper, written for this page.

The framework collects server measurements under varying workloads and trains an offline reinforcement-learning controller. Dynamic GPU clock decisions are combined with interval fan control and Q-network pre-training. Evaluation on an NVIDIA L40S server reports workload-dependent power savings and execution-time trade-offs.

The problem

Why this problem matters

Lower clock speeds can save power but prolong a task; faster cooling also consumes power. Control must consider these coupled effects at the server level.

From problem to solution

How the method works

Build a representative dataset

Synthetic workloads produce logs of temperature, utilization, frequency and power. Dataset coverage matters because the deployed policy learns from these recorded operating conditions.

Sections III–IV, dataset construction

Train and deploy the controller

The proposed TD3+BC-based method includes Q-network pre-training and interval fan control. Its reward penalizes power use and prolonged execution.
